# AI 참고 제안 (담당자 확인 항목)

Source: 팀장 결정 2026-11-17 — 실제 공고문에서 AI 기준 제안이 하나도 붙지 않는 문제를 "담당자 확인 칸에도 AI 제안을 참고로 표시"하는 방법으로 푼다.

## Goal

실제 공고문을 올렸을 때, 규칙이 "담당자 확인"으로 돌린 기준 문장에 대해 AI가 읽은 조건을 참고로 보여 준다. 담당자는 기준을 직접 정할 때 근거 문장과 AI가 읽은 값을 함께 본다. 기준을 정하고 확정하는 일은 지금처럼 담당자가 한다.

## Background

- 실측(`.trellis/tasks/11-16-jbai-llm-stabilize/report.md` 8절): 실제 공고문 3종에서 받은 제안 30건은 인용이 모두 원문과 일치했다. 27건은 추출기가 "담당자 확인"으로 분류한 문장을, 3건은 추출기 후보가 없는 문장을 짚었다. 붙은 제안은 0건이다.
- 지금 규격: 제안은 `engine_rule`이 있는 자동 후보에만, 모델이 쓴 값이 후보의 값과 같을 때만 붙는다. 붙은 제안에는 후보의 값이 실린다.
- 제안은 분석 직후의 초안에만 있다. 담당자가 초안을 저장하면 서버가 제안을 보존하지 않는다. 화면에서는 "추가 안내" 목록의 카드로 보이고, 카드에서 공고문 쪽 보기·항목으로 이동·제안 제외를 할 수 있다.
- 코드 근거는 `research/findings.md`에 있다.

## Requirements

- **R1 참고 제안 만들기** — 모델의 기준 제안이 자동 후보에 붙지 못했을 때, 인용한 문장에 추출기의 "담당자 확인" 후보가 있으면 그 후보를 대상으로 하는 참고 제안을 만든다. 추출기 후보가 없는 문장에는 만들지 않는다.
- **R2 문장에 적힌 값만** — 참고 제안에 보여 주는 값은 모델이 쓴 값 중 그 종류의 직접 값(나이, 출생일 범위, 시·도, 발급 기준일, 중위소득 비율, 근속 개월)뿐이다. 그 값이 모두 인용 문장 안에 실제로 적혀 있어야 한다. 하나라도 문장에서 확인되지 않으면 그 제안은 버린다.
- **R3 기준은 바뀌지 않는다** — 참고 제안은 표시 전용이다. 기준 후보의 종류·값·자동 규칙 연결, 담당자 확인 여부, 게시 조건을 바꾸지 않는다. 값을 기준에 자동으로 넣는 기능은 만들지 않는다.
- **R4 자동 후보가 우선** — 같은 문장에 같은 종류의 자동 후보가 있으면 참고 제안을 만들지 않는다. 그 경우는 지금의 규칙(값 일치 시 제안, 아니면 버림)이 그대로 적용된다. 추출기가 그 문장에서 읽은 값과 모델의 값이 다르면 참고 제안을 만들지 않는다.
- **R5 화면 표시** — 참고 제안 카드는 기존 제안 카드와 구분되는 표시("AI 참고")와 "AI가 읽은 조건" 한 줄(종류와 값)을 보여 준다. 근거 문장, 공고문 쪽 보기, 항목으로 이동, 제외는 기존 카드와 같다. 기존 "AI 제안" 카드의 동작은 바뀌지 않는다.
- **R6 기록과 확인 도구** — 호출 기록의 검증 요약에 참고 제안 수를 더한다. 확인 도구는 참고 제안을 통과로 세고, 화면 위반 검사에서 참고 제안의 조건(R2)을 다시 검증한다.
- **R7 실측** — 실제 공고문 3종(전과 같은 PDF)을 3회씩 다시 재고, 합성 공고문 3종으로 기존 결과가 유지되는지 확인한다. 전북AI를 켠 격리 서버에서 화면을 한 번 확인한다.
- **R8 규격과 문서** — `.trellis/spec/backend/notice-drafts.md`, `.trellis/spec/frontend/program-authoring.md`(해당 시), `docs/DEVELOPMENT.md`를 갱신한다. 의도적으로 바꾼 시험 기대값을 목록으로 남긴다.

## Acceptance Criteria

- **AC1 (R1, R7)** 실제 공고문 3종 모두, 3회 중 3회에서 참고 제안이 1개 이상 나온다(지금은 0).
- **AC2 (R2)** 참고 제안의 값은 모두 인용 문장에서 확인된다. 가짜 응답 시험으로 종류별 통과·버림을 확인하고, 실측의 화면 위반은 0이다.
- **AC3 (R3)** 참고 제안이 있어도 초안의 `criteria`, `guidance`(AI 안내문 제외), 게시 차단 사유가 참고 제안이 없을 때와 같다. 담당자 확인 후보가 자동 후보로 바뀌는 경우는 없다.
- **AC4 (R4)** 자동 후보가 있는 문장, 추출기 값과 충돌하는 값, 후보 없는 문장, 문장에 없는 값에는 참고 제안이 생기지 않는다.
- **AC5 (R5)** 프런트 단위 시험으로 카드 표시 문구를 확인하고, 화면 확인에서 "AI 참고" 카드가 보인다. 프런트 `tsc`, `oxlint`, 빌드, 단위 시험이 통과한다.
- **AC6 (R7)** 합성 공고문 실측에서 기준 제안 통과가 유지된다(A 4, B 2, C 1).
- **AC7** 엔진·백엔드·시나리오 게이트가 변경 전 같은 PC의 기준 결과와 같거나 좋다. 보호 파일 10개 변경 0.
- **AC8 (R8)** 규격과 문서가 새 동작과 일치한다.

AC1은 실제 모델에 달려 있다. 미달하면 원인과 함께 그대로 보고한다.

## Out of Scope

- 참고 제안의 값을 기준에 넣어 주는 "반영" 버튼.
- 추출기 후보가 없는 문장에 대한 제안(AI가 새 기준 항목을 만드는 일).
- 규칙 추출기(`notice_analysis.py`) 보강, 제목 후보를 찾지 못하는 문제.
- 저장한 뒤에도 제안을 유지하는 일(지금처럼 분석 직후에만 보인다).
- 신청자 화면. 참고 제안은 담당자 화면에만 나온다.

## Key Decisions

- **D1** 참고 카드에 AI가 읽은 값을 보여 준다. 단, 인용 문장에 실제로 적힌 값만 보여 준다(2026-11-17 팀장이 고른 방안의 내용).
- **D2** 확정은 담당자가 한다. 자동 반영은 없다.
- **D3** 같은 문장에 자동 후보가 있으면 참고 제안은 만들지 않는다. 충돌하는 읽기를 참고로 내보내지 않기 위해서다.
- **D4** 브랜치는 `feat/ai-reference-suggestions`이고 `feat/jbai-llm-stabilize`에서 분기했다. 안정화 PR이 병합된 뒤 별도 PR로 올린다.

## Risks

- 모델이 값을 잘못 읽을 수 있다. R2(문장에 적힌 값만)와 "AI 참고" 표시로 줄이지만, 담당자가 참고를 그대로 믿을 위험은 남는다.
- 실제 호출이 약 16회 필요하다(실제 공고문 9, 합성 6, 화면 확인 1). 매 묶음마다 승인 후 실행한다.
- 이 브랜치는 안정화 PR 위에 쌓여 있다. 안정화 PR이 리뷰에서 바뀌면 다시 맞춰야 한다.
